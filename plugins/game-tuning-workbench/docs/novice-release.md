# 小白闭环：0.4.0-beta.1

## 用户现在怎么用

在游戏所在 Codex 任务里说“打开这个游戏的调优工作台”。启动器完成分析、生成、选空闲端口与打开页面。第一次只选“先看看”或“允许修改”，不再选择只读/草稿/应用三种技术工作台。

主流程：

1. 认识游戏：手感、故事、玩法流程、素材参考。
2. 试着改一点：修改暂存到这台电脑，不立即覆盖游戏。
3. 看看改了什么：准备方案，试玩临时副本，最后确认保存。
4. 检查与恢复：查看构建、截图与日志，亲自确认玩法，不满意时撤销。

## 实现分工

| 模块 | 职责 |
| --- | --- |
| `open-workbench.mjs` | 单入口分析、生成、启动、复用已有服务、打开浏览器 |
| `novice.js` / `novice.css` | 新手向导、渐进页面、生活化文案、图文与候选对比 |
| `novice-service.mjs` | 授权、本地草稿、Codex 方案任务、范围检查、确认事务、回执与恢复 |
| `runtime-preview-service.mjs` | 原版和修改版的临时副本，兼容数值与复杂文本方案 |
| `smoke-evidence.mjs` | 自动打开游戏，记录画布、错误、截图，不代替人工玩法检查 |
| `release-check.mjs` / `package-release.mjs` | 发布门槛、隐私扫描、安装目录、校验清单 |

旧的三个页面生成器和 API 保留给已有使用者；新入口只暴露带会话校验的统一 API，不允许绕过新手授权调用旧写入接口。

## “让 Codex 实施”不会跳过确认

数值按精确位置生成方案。故事、规则由现有 Codex 登录驱动的只读 CLI 工作者生成完整文件方案。它只接收选中内容的源码，不直接写游戏，不加载用户自定义配置或插件。输出文件必须在允许范围内，不能顺手改掉未选中的已识别数值。

方案准备和源码应用分开。确认页显示修改清单、效果、未涉及内容和折叠的文件前后对照；真正写入时校验文件仍和准备时一致。内容已变化就停止，不把其他人的改动覆盖掉。

恢复采用“整文件前后版本 + 一致性检查”。它不是任意时间点的一键倒带：如果文件后来被修改，撤销会被拦截，需要合并。应用中断会留下可恢复记录。构建失败不标记成功，也不自动删掉用户的新工作。

## 哪些仍不是完整能力

- 自动证据目前是加载/画布/错误/截图检查，以及常见开始按钮；没有针对每个游戏编写通关机器人，不能证明复杂行为满足预期。
- 图文世界观的图片是本地参考，素材对比当前支持 PNG/JPG/WebP。三方生图、生模型未选服务，3D 预览、加载约束适配与实际素材替换仍需接入；界面不允许假应用。
- 复杂修改限制在当前选中内容已绑定的源码范围。跨系统、新增模块、大规模改造不自动扩大权限。
- 当前参数分析沿用显式配置适配器，不保证任意 Three.js 项目都能自动找到足够参数。
- 0.3 浏览器草稿不会跨地址自动导入。旧生成器继续可用；新版草稿用本地文件保存。
- GitHub Git marketplace 可供用户安装；尚未上架 OpenAI 公共插件目录。

## 建议按这个顺序验收

1. 在测试游戏打开工作台，选“先看看”：参数不可拖动，当前游戏可以试玩。
2. 点“允许修改”：拖一个滑杆，刷新后草稿仍在，原始文件不变。
3. 在“看看改了什么”试玩两个版本：区别符合数值修改；游戏原始文件仍不变。
4. 点准备修改，不勾确认时保存按钮禁用；勾选后保存，检查结果与截图出现。
5. 试玩并检查影响/未影响项。缺构建或自动截图失败时，不能标记全部完成。
6. 点击撤销：原始文件恢复；如果先用另一个工具改过文件，撤销必须停止且保留新改动。
7. 改故事或规则：按钮直接调用 Codex，不下载 JSON；确认前不写入，确认后记录完整前后文件。
8. 添加参考图片和素材候选：并排查看与选择，刷新后保留；不能将图片参考误报成游戏内模型已替换。
9. 停止服务再启动：授权回到“先看看”，草稿与历史仍在。若上次操作被中断，应提示恢复。

自动化命令：`npm test`、`npm run test:integration`、`npm run check`。发布前还要运行 `node scripts/package-release.mjs --public`；没有通过就只产出本地测试包。
